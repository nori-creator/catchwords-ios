# 言語の規則（言語が混ざらないための決まり）

CatchWords の画面には、3種類の言葉が同時に出る。

| 種類 | 何か | 例 |
|---|---|---|
| **表示言語**（＝母語） | アプリの文字と、AI が書く解説の言語。ja / en / zh-TW / es / ko / vi（一覧は `ios/Localization/languages.json` の1つだけ。足し方は [adding-a-display-language.md](adding-a-display-language.md)） | ボタン、意味、例文の訳、チャンクの訳、量詞の注記、日記の添削の解説 |
| **学習言語** | 学んでいる言語。zh-TW / en / ja | 見出し語、読み、例文、チャンクの語、4択の選択肢 |
| **固有の名前** | 言語に関係なく同じ表記 | CatchWords、YouTube、Weblio、言語の自称（日本語 / English / 繁體中文 / Español / 한국어 / Tiếng Việt） |

**決まりは1つだけ：** どの画面のどの文も「表示言語」か「学習言語」のどちらかで、その役目どおりの言語で出す。
それ以外の言語の文は、**出さない（空にする）**。間違った言語で読ませるより、「まだ無い」と描くほうが正しい。

## 規則

| 番号 | 規則 | 強制している場所 | 自動検査 |
|---|---|---|---|
| R1 | アプリが書く文はすべて `L(...)` を通し、**一覧のすべての表示言語の訳**を持つ。欧文の言語（英語・スペイン語・ベトナム語）の訳に**かな・漢字・ハングルを入れない** | `Utilities/L10n.swift` | `scripts/check_l10n.py`（CI） |
| R2 | 台湾華語訳に**かな・ハングルを入れない**。韓国語訳に**かな・漢字を入れない** | 同上 | 同上 |
| R3 | 訳が**元の文の写し**（訳していない）なら、どの言語でも出さない | `LanguageRules.looksWrong` | `ios/LanguageRules/cases.json`（CI） |
| R4 | 日本語の読者：かなの無い漢字だけの長い文（≥5字）は中文、欧文だけの文は英語として出さない。短い意味（鉄板焼・故宮博物院）は漢字だけでも日本語 | 同上 | 同上 |
| R5 | 台湾華語の読者：かなが文の大半を占めれば日本語、欧文だけの文は英語として出さない。中文の中で引用した1語のかなは残す | 同上 | 同上 |
| R6 | 英語の読者：漢字・かなが欧文より多い文は出さない。英文の中の見出し語（鐵板麵）は残す | 同上 | 同上 |
| R7 | サーバ・端末のエラー文：表示言語で書かれていれば出す。既知の日本語のサーバ文は訳す。それ以外は表示言語の一般的な文に置き換える | `L10n.readerSafe` / `LanguageRules.readsAs` | `cases.json` |
| R8 | 例文は、**学習言語で書かれている物だけ**出す（英語の学習者に中文の例文を出さない） | `LanguageRules.isIn` | `cases.json` |
| R9 | 「」『』“” で引用された語は判定から外す（引用は学習言語の例であって、解説の言語ではない） | `LanguageRules.unquoted` | `cases.json` |
| R10 | サーバが書いた文（意味・訳・注記・理由・添削）は、**必ず読む人の言語のフィルタを通して**画面に出す。図鑑・単語の詳細・復習の語は `DexStore` が読む人向けに解決した物を使う | `ReaderLanguage.resolve` / `ReaderLanguage.shown` | `scripts/check_server_text.py`（CI） |
| R11 | 単語の解説は**読む人の鍵（表示言語 × 母語）ごとに別の行**（`word_explanations`）。共有の語の行の解説は、言語の印が表示言語と同じときだけ使う。印の無い古い解説を、読む人の行に**保存しない** | `DexStore.loadExplanation` / `shownExtras` | レビューで確認 |
| R12 | 入力欄の例・見本は**学習言語の語**を `NativeAPI.sample` から入れる。翻訳表に学習言語の語を書かない | `NativeAPI.sample` | `check_l10n.py`（R1 と同じ検査） |
| R13 | AI への指示文を端末に置かない。サーバの関数（`/api/native-fn`）が、表示言語と学習言語を自分で読んで書く | `Services/AIService.swift` | レビューで確認 |
| R14 | 英語の数：`{1} words` の 1 は単数（1 word） | `L10n.fill` | レビューで確認 |
| R15 | 見出し語は学習言語の文字だけ。保存された言語に合わない語は、合う言語へ1つに決まるときだけ付け替える（日本語へは付け替えない） | `LanguageRules.headwordOk` / `resolveWordLanguage` | `cases.json`（`headwordOk` / `resolveLanguage`） |
| R16 | 単語の詳細の項目は**学習言語ごと**（量詞・台湾メモは台湾華語だけ、活用形・冠詞・強勢・句動詞・文化の一言は英語だけ、漢字の内訳・活用・敬語・助数詞・アクセント・語種・日本メモは日本語だけ）。「語源・部首」は部首のある言語だけ。並びと表示の好みも言語ごとに覚える | `CardSection.sections(for:)` / `CardPrefsStore.use` | レビューで確認 |
| R17 | 読みは学習言語の物だけ：台湾華語＝注音/ピンイン、日本語＝ふりがな/ローマ字、英語＝読みを出さない。読みの設定も言語ごと | `ZhuyinWordView` | レビューで確認 |
| R18 | 復習は学習言語の語だけ：問題・件数・連続日数・保持率・通知の時刻・4択の受け皿。学習言語を変えたら作り直す | `ReviewStore` / `DexStore.upcomingDueTimes` | レビューで確認 |
| R19 | 読み上げは**その文の言語**の声で（かな→日本語、欧文→英語、漢字→学習言語） | `SoundService.language(of:)` | レビューで確認 |
| R20 | 使い方の型（チャンク）には（チャンクの表示ルールの全体は [chunk-rules.md](chunk-rules.md)）**学ぶ語そのもの**（日本語・英語は活用形も可）を必ず入れる。「芒果」の型に「很+甜」だけを出さない。入っていない型は表示しない | `LanguageRules.mentionsHeadword`（答えの画面・単語の詳細）、Web `refineUsageChunks` と指示文 | `cases.json`（`mentionsHeadword`） |
| R21 | 単語の画像を探す言葉は**読む人の意味の最初の語義**（括弧・〜を落とす）。見出し語（例: 腳踏車）で探すと通販の写真や字の画像が返る。意味が空なら見出し語 | `LanguageRules.heroSearchQuery`（`WebImages.search`）、Web `heroSearchQuery` | `cases.json`（`heroSearchQuery`） |
| R22 | 判定は**読む人の言語の書く文字**ごと（かな / 漢字 / ハングル / 欧文）。欧文の言語どうしは文字では分からないので、**別の欧文の言語だとはっきり分かる文**（その言語だけの語・文字が2つ以上で、ほかの言語の2倍以上: "the … of" をスペイン語の読者に、đ ơ ư を英語の読者に）を出さない。手がかりの無い短い語（bus stop）は残す。韓国語の読者には、ハングルの無い文と、漢字・かながハングルの2倍より多い文を出さない。共有の語の行は、文字ではなく行の言語の印で選ぶ（R23） | `LanguageRules.looksWrong` / `latinLanguage`、`ReaderLanguage.resolve`、Web `note-language.ts` / `meaning-language.ts` / `explain-languages.ts` | `cases.json`（`L-es-*` / `L-ko-*` / `L-vi-*` / `L-en-*`）、Web `explain-languages.test.ts` |
| R23 | **共有の語の行（意味・例文訳・解説）は、行の言語の印（`explain_lang`、印の無い古い行は日本語）の読者にだけ出す**。文字で選ばない（英語とスペイン語、日本語と中文の漢字だけの意味は文字で見分けられない）。別の言語の行の解説は、学ぶ言語の部分（チャンクの文・語形・漢字・量詞）だけ残し、説明の文をすべて空にする。サーバは、行の言語と同じ言語の人だけが空の所を埋め、何も無い行は最初の人の言語の行にして印を付ける | iOS `ReaderLanguage.resolve` / `sharedTextIsFor` / `learningOnly`、Web `shared-word-guard.ts`（`mayWriteSharedReaderText` / `claimSharedRowLanguage`）、`applyWordExtrasUpdate`・`fillSharedWordFromCard`・`runSectionRegen`・`reportAndFixSection`・`fillReaderMeanings` | Web `shared-word-guard.test.ts`（共有の行の言語）・`generated-cards.test.ts` |
| R24 | **保存した場所の名前**は、保存した時の言語のまま。座標があれば表示言語で引き直し、無い・引けない時は、表示言語として読める名前だけ出す（読めなければ場所を出さない） | `LocationService.shownPlace` / `localizedName`、`LocalizedPlaceText` | `scripts/check_server_text.py`（`place` / `locationName`） |

判定の中身は `ios/CatchWords/Utilities/LanguageRules.swift` に1つだけ置く（Web版 `note-language.ts` の
`looksWrongForReader` と同じ考え方）。**画面ごとに判定を書かない。**

## 違反が見つかったときの手順（規則は検査するほど厳しくなる）

1. **事例を記録する**：下の「事例の記録」に、日付・画面・何が何語で出たか・原因を書く。
2. **検査ケースを先に足す**：その文を `ios/LanguageRules/cases.json` に入れる（`expect` は正しい答え）。
   CI が赤くなることを確かめる（＝今の規則では防げていなかった証拠）。
3. **規則を直す**：`LanguageRules.swift` を、**新しいケースと過去のケースが全部通るまで**直す。
   過去のケースを消したり `expect` を書き換えたりして通してはいけない。過去の事例が同じ形で
   再発しないことが、この表の役目。
4. **表示の道を塞ぐ**：その文が通った道（フィルタを通らずに出た画面）を `check_server_text.py` の
   対象に足す。新しい種類のサーバの文なら、その欄の名前を `FIELDS` に足す。
5. **規則の表を更新する**：上の表に規則を足すか、既存の規則の説明を書き直す。

> 規則を「ゆるめる」変更は、それで消えてしまう正しい文の例をケースに足したときだけ認める。

### iOS 版（2026-10-01 の言語の検査）

| 事例 | 画面 | 何が起きたか | 原因 | 対策 |
|---|---|---|---|---|
| IOS1 | 単語の詳細・図鑑・復習 | 英語・台湾華語の読者に、共有の語の日本語の意味・チャンクの訳が出ていた | iOS が `words` の共有の行だけを読み、読む人の解説（`word_explanations`）を読んでいなかった | R10・R11。`DexStore` が読む人向けに解決 |
| IOS2 | 単語の詳細 | 台湾華語の読者向けの中文の注記が、かなの語を1つ引用しただけで消えていた | 「かなが1文字でもあれば日本語」の判定 | R5・R9 |

### Web 版の過去の事例

Web版のコードの注記（「オーナー報告」「βテスト」「R17」など）にある言語の混在の事例は、
`docs/language-incidents-web.md` に1件ずつ、画面・原因・規則・iOS での対応状況と一緒にまとめる。
各事例の具体的な文は `cases.json` のケース（id が `W` で始まる）として入れ、同じ形の再発を CI で止める。
