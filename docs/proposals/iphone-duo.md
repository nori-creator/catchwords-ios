# iPhone Duo 対応の提案（2026-10-24、オーナーの依頼「アイディア出して」への答え）

> まだ**案**。オーナーが選んだものだけを実装する。選んだら CLAUDE.md の「オーナーの決定」に書き足す。

オーナーの元の案（2026-10-24）:
- A. 左ページ＝切り抜きステッカー、右ページ＝日記。ページをめくれる。
- B. 左ページ＝切り抜きステッカー、右ページ＝単語の詳細。
- 条件: 「iPhone Duo の特性を生かして最大限かっこいい、ユーザーが快感を覚える機能。今のアプリにないものを足す」。

**結論（先に）**: 土台は **B**（左＝その日の紙のアルバム、右＝選んだ語の「ページ」。語を替えると右ページがめくれる）。
A の日記は、iOS 版に日記の機能がまだ無く（ロードマップ §2 は未着手）、Apple Pencil の対応も「今年中」でまだなので、**第3段**に回す。
Duo でしかできない「快感」の中心は、ページの中身ではなく **折り目（ヒンジ）を操作にする**こと: ①**本を開いて答えを見る復習**、②**閉じて撮る → 開くと図鑑に舞い降りる**、③**外側の画面で相手に単語を見せる**。下に全部書く。

## 1. iPhone Duo とは（確かめた範囲。初心者向けの言葉の説明つき）

| 項目 | 内容 | 出どころ |
|---|---|---|
| 発売 | 2026-09-09 発表、**2026-10-23 発売**（昨日） | MacRumors、GSMArena |
| 画面 | **外側 5.4 インチ**（閉じた時。今の iPhone より「幅が広く、背が低い」）、**内側 7.6 インチ**（開いた時。本のように縦の折り目で開く） | MacRumors、Apple Tech Talk「Design for iPhone Duo」 |
| 形 | 本型（左右に開く）。閉じて 11.3 mm、開いて 5.2 mm、254 g | MacRumors |
| OS | **iOS 27.1**。開発は **iOS 27.1 SDK**（Xcode 27.1）。Xcode 27.1 の **Device Hub** で、シミュレーターを折ったり回したりして試せる | Apple Newsroom 2026-10 |
| 認証 | 側面ボタンの Touch ID（Face ID なし） | MacRumors |
| Apple Pencil | **USB-C の Apple Pencil が内外どちらの画面でも使える**。ただし **「今年中に」の後出し**で、発売時点では使えない | TechRepublic、Android Authority（Apple の注記を引用） |
| 他のアプリと並べる | **Split View**（画面を左右 50/50 に分けて2つのアプリ）。全アプリが対象 | Tech Talk 111464 |

用語:
- **ヒンジ**: 折り目の金具。Duo は「閉じている / 半分開いている / 全開」の3状態と、**開いた角度（連続した数値）**をアプリに知らせる。
- **姿勢（ポーズ）**: Apple の資料に出てくる持ち方。(1) 閉じて外側画面、(2) **本のように半分開く**（折り目が縦）、(3) **机に置いてノート PC のように立てる**（折り目が横。上半分が画面、下半分が机に接する）、(4) **縁で立てる**（写真立てのように自立）。
- **SDK**: アプリを作るための部品一式。「iOS 27.1 SDK で作り直す」と、Duo の新しい部品（下の API）が使える。古い SDK のままでも動くが、内側画面では「見慣れた大きさの枠」の中に表示されるだけ（全面にならない）。
- **API**: アプリが OS に頼みごとをする窓口。Duo 向けに増えたのは次の4つ。

| API（SwiftUI の名前） | 何ができるか | Apple の使い分け |
|---|---|---|
| `onHingeChange` | ヒンジの状態（閉 / 半開 / 全開）と**角度**を受け取る | 「**演出や操作**に使う。レイアウトには使わない」 |
| `ArrangementView`（split / overlay） | 2つの画面部品を、折り目に合わせて**左右に分ける**か**重ねる**か、OS が決めて並べる | 「主と従（一覧と詳細）」なら split |
| `reservedRegions(kind: .division / .occlusion)` | **折り目の帯**（division）と**カメラの穴**（occlusion）の位置を取る | 自分で置いているボタンを折り目から逃がす |
| `sceneAccessory { CameraCaptureAccessory { … } }` | **内側でカメラを使っている間、外側の画面に別の表示を出す** | 「撮られる人に何かを見せる」 |

Apple の設計の指針（Tech Talk「Design for iPhone Duo」「Strike a pose」）:
- 「姿勢ごとに別のレイアウトを作るな。**外側＝コンパクト幅、内側＝レギュラー幅**の2つの size class で考えろ」。
- 「固定の幅・特定の画面に結びついた数値を避け、**自由に伸び縮みする**ように作れ」。
- 半分開いた時、**押せる物は折り目の上に置かない**（OS の部品は自動で避ける。自作の物は `reservedRegions` で避ける）。スクロールする中身は避けなくていい。
- 机に立てた姿勢では「**上半分＝遠くからでも見える中身、下半分＝触る操作**」。
- 内側画面では「**2列（一覧＋詳細）**」。

## 2. CatchWords の特徴（Duo の目で見直す）

iOS 版の今の構造（コードから）:

| 画面 | 中身 | Duo での意味 |
|---|---|---|
| ホーム | 日ごとの**紙のアルバム**。切り抜きステッカーを2枚ずつ並べ、長押しで動かす・回す（`CollageBoard`、`AlbumLayout.packDay`） | すでに「アルバム＝紙」。**Duo は本そのもの**。開く＝本を開く |
| 図鑑 | 分類ごとの白いカードに 4 列の升目。星が舞い降りる（`DexGallery`、`CatchLanding`） | 一覧。右に詳細を置くと「見開き」になる |
| カメラ | 撮る → 光のペンが輪郭をなぞり名前の札が出る → 選ぶ → GET の舞台 → 図鑑へ飛ぶ（`CatchScan`、`CatchStage`、`CatchCelebrationView`） | **片手でさっと撮るのは閉じた外側画面**が向く。演出は開いた大画面が映える |
| 単語のページ | 写真（自撮りにひっくり返る）、意味、使い方①②③（公式＋例文＋読み）、量詞、関連語、台湾メモ、出会いの履歴、忘却曲線 | **右ページの中身はもう全部ある**（B 案はすぐ作れる） |
| 復習 | 4択。写真と4つの選択肢が1画面に収まるよう高さを計算（`QuizCard.fitHeight`） | 「問題と答えを分ける」のに折り目が使える |
| 日記 | **iOS には無い**（ロードマップ §2 は未着手。Web には鉛筆の 3D 演出 `diary-pencil` だけ） | A 案は先に日記を作る必要がある |
| 保存している情報 | 撮った場所の名前、時刻、再会の回数、記憶の確率 | 右ページの「その日の記録」に使える |

アプリの核は「**自分の暮らしで出会った物が、切り抜きのステッカーになって、自分のコレクションが育つ**」（Web の PRODUCT.md「My own collection/world is growing」）。
Duo で一番伸びるのはこの「コレクションを**手で開いて眺める**」部分で、学習の仕組み自体を変える必要はない。

## 3. 開いた時に何を見せるか（姿勢ごとの答え）

### 3-1. 閉じている（外側 5.4 インチ）＝「捕まえる」

- 今の iPhone と同じ5つのタブ。**撮る → 札 → 選ぶ**まではここで終える（片手、素早く）。
- 外側は今の iPhone より幅広・背が低い。復習の 4択は `fitHeight` の計算で収まる見込み。確かめる。
- 変える所: タブバーの横幅の上限 400 pt（`CapsuleTabBar`）はそのまま使える。

### 3-2. 本のように開く（内側、折り目が縦）＝「見開きのアルバム」【B 案を土台】

左ページ: **その日の紙**（今のホームの1日ぶん。2枚ずつ並ぶ規則は変えない）。
右ページ: **選んだ語の「ページ」**。単語の詳細の中身を、本の1ページとして組み直したもの:
1. 切り抜き（大きく）、見出し語＋注音/ピンイン、音声ボタン
2. 意味
3. 使い方①（場面の一言 → 公式 → 例文。②③は下にスクロール）
4. 下の余白に: 撮った日時・場所、再会 n 回目、記憶の確率
語を選んでいない時の右ページ: **その日の目次**（日付、場所、「n 語」、その日の語の一覧）。

動き:
- 左のステッカーを押す → **右ページだけが紙のようにめくれて**次の語になる（左は動かない）。
- 左右にスワイプ → **見開きごと**めくれて前の日 / 次の日（オーナー案の「ページめくれる」）。
- 実装は `ArrangementView`（split）に左右を渡す。折り目に合わせて左右に分かれ、Split View で半分になった時や外側画面では「左だけ」に戻る（OS がやる）。

注意（正直に書く）:
- iPhone 版のホームは「**1本の縦スクロール。横に滑らせない・めくらない**」と決めてある（`HomeView` 冒頭のコメント）。見開きとページめくりは **Duo の内側画面だけ**の見た目にする。外側画面と今の iPhone は変えない。
- 左ページの紙は、幅が今の iPhone とほぼ同じになる見込み（内側≒外側2枚ぶん）。なので `AlbumLayout` の置き方はそのまま使える可能性が高い。Device Hub で確かめる。

### 3-3. 机に立てる（折り目が横、ノート PC の形）＝「置いて復習」

- 上半分: ステッカーの写真（大きく）と問題文。下半分: 4つの選択肢と音声ボタン（Apple の「上＝見る、下＝触る」そのもの）。
- 食事中・机の上で、**手で持たずに**復習できる。音声は上から出て、指は下だけ。
- GET の舞台も同じ配置: 上にステッカーの舞台、下に「戻る」と「図鑑に追加」。
- 必要な変更: 今のアプリは**縦向きだけ**（`UISupportedInterfaceOrientations_iPhone = Portrait`）。この姿勢は横向きなので、**Duo では横向きを許す**必要がある。これは全画面に影響する作業（下の「土台」）。

### 3-4. 縁で立てる（写真立て）＝「飾る」

- 「今日の単語」ウィジェット（`TodayWordWidget`）の中身を、内側の画面いっぱいに。その日のステッカーが数秒ごとに入れ替わり、語と読みが出る。音は出さない。
- 机に置いておくだけで復習になる。実装は軽い（既にある部品）。

## 4. Duo でしかできない機能（新しく足すもの。快感の強い順）

### ① 本を開いて答えを見る復習（ヒンジ＝めくり）

半分開いた本の形で復習する。**左ページ＝問題**（写真と意味）、**右ページ＝答え**（語・読み・例文）。右ページは、ヒンジの角度が**ある角度を越えるまで紙で伏せてある**。思い出してから、本を**さらに開く**と右ページがめくれて答えが出る。閉じ気味に戻すとまた伏せる。
- `onHingeChange` の角度で紙の「めくれ具合」を**連続で**動かす（角度に指が追従するので気持ちいい）。音は `cc-tick`、振動は選択。
- 「思い出してから答えを見る」は、4択より強い記憶の証拠（PRODUCT.md「recognition → recall」）。採点は**自己申告の2択**（「思い出せた / 思い出せなかった」）。サーバの `gradeReview` に新しい形式の印を足す必要がある（iOS と Web で次回日がずれないように）。
- Apple の指針どおり、角度は**演出と操作**だけに使い、レイアウトは `ArrangementView` に任せる。
- 平らに全開した時・外側画面では、今までの 4択に戻す（Duo でない端末と同じ）。

### ② 閉じて撮る → 開くと図鑑に舞い降りる

外側画面で札を選んで GET まで終える。その状態で**本を開く**と、内側に図鑑の見開きが現れ、星（ステッカー）が**折り目を越えて**自分の升目に飛んで入る（今の `CatchLanding` の弧を、2ページぶんの幅で描く）。
- ヒンジが「閉 → 開」になった瞬間を `onHingeChange` で受け、`AppRouter.landing` を起こす。
- 開かなければ、今まで通り外側画面の中で着地する（開くのは任意）。
- 「捕まえる（閉）→ しまう（開）」が、体の動きと一致する。これが Duo の「快感」の中心だと思う。

### ③ 外側の画面で相手に単語を見せる（`CameraCaptureAccessory`）

内側を開いてカメラを使っている間、**外側（被写体側）の画面**に、いま出た札の語・注音・意味を大きく出す。
- 台湾の屋台で店の人に向けて「これ、こう言うんですよね？」と**見せて確かめる**。相手が読める繁體字で出る（表示言語の規則 R23 どおり、相手向けの面は zh-TW のみ）。
- 友達を撮る時は、外側に「3・2・1」とシャッターの合図、撮れた切り抜きのプレビューを出す。
- Apple の例（テレプロンプター）と同じ仕組み。内側でカメラ全画面の時だけ使える（OS の制限）。

### ④ 置いて復習・置いて飾る（3-3、3-4）

上に書いたとおり。新しい部品は少ないが、横向き対応が前提。

### ⑤ Apple Pencil（対応が出てから）: 書き取りと日記【A 案はここ】

- 右ページに**その字をなぞる**升目（注音も）。自分の筆跡で書く。手書き風フォントは使わない決まりだが、**本人の手書きそのもの**なので別。
- 日記（ロードマップ §2）: 左ページ＝その日のステッカー、右ページ＝鉛筆で書く日記。赤ペンの添削は Web の案のまま。
- 着手の条件: Apple が Pencil 対応を出すこと（「今年中」）。それまでは指で書けるが、価値が落ちる。**日記そのものを先に作る**必要がある（AI の添削の費用設計、1日の上限）。

### ⑥ ほかのアプリと並べる（Split View）

Google マップや LINE を左、CatchWords を右に。新しい機能ではないが、**伸び縮みする作り**（下の土台）ができれば自動で使える。

## 6. 作る順番（段階。どこで止めてもアプリは壊れない）

### 第0段: 土台（Duo で**まともに表示される**まで。他の全部の前提）

1. Mac と CI の Xcode を **27.1** に上げ、**iOS 27.1 SDK** で作る（Duo の API は `if #available(iOS 27.1, *)` で囲む。最低対応 iOS 18 は変えない）。CI（GitHub Actions）の macOS イメージに Xcode 27.1 が来ているか確かめる。無ければ Duo の確認は手元の Mac だけ。
2. **固定幅をなくす**: 図鑑の 4 列（`DexGallery.columns`）→ 幅に応じて 4〜8 列。GET の舞台の「1080 × 2340 の画面の割合」（`Film6`）→ レギュラー幅での見え方を確かめる。復習の `fitHeight` → 横向きでも計算が合うか。
3. **折り目を避ける**: 自作のタブバー（`CapsuleTabBar`）は中央にカメラの丸があり、半分開くと**ちょうど折り目の上**に来る。`reservedRegions(kind: .division)` で、半開の時は左ページの下に寄せる（または左右に分ける）。
4. **横向きを許す**（Duo の机置き姿勢のため）。今は縦だけ。横向きで崩れる画面を全部直す必要があるので、ここが第0段で一番重い。Duo の時だけ許す方法が無いか SDK で確かめる。
5. Device Hub で 4 姿勢 × 5 タブの画像を撮り、`ci-previews` に入れる（最新1コミットだけの規則どおり）。

### 第1段: 見開きのアルバム（§3-2、B 案）

- `ArrangementView(split)` に左＝その日の紙、右＝語のページ（新しい `WordPageView`。`WordDetailView` の部品を本のページとして並べ直す）。
- 右ページだけのめくり（`rotation3DEffect` で紙の半分をめくる。`reduceMotion` では切り替えだけ）。
- 見開きごとの日送り。

### 第2段: ヒンジと外側画面（§4 ①②③）

- ① 開いて答えを見る復習（サーバの `gradeReview` に新しい形式を足す。Web リポジトリの `src/lib`）。
- ② 閉じて撮る → 開くと着地。
- ③ 外側画面に語を出す（`CameraCaptureAccessory`）。

## 7. 危うい所・分からない所（正直に）

- **実機が無いと分からない事が多い**。シミュレーターの Device Hub で姿勢は再現できるが、ヒンジの角度を連続で変える手触り、外側画面の見え方、カメラ（Vision の切り抜きはシミュレーターで動かない）は実機でしか確かめられない。
- **横向き対応は全画面に波及する**。ここを省くと §3-3、§3-4、§4 ④ は作れない。見開き（§3-2）と §4 ①②③ は縦向きのままでも作れる。
- **ヒンジの状態の名前**: Apple の動画で確認できたのは `.partiallyOpen` だけ。「閉」「全開」の正確な名前は SDK で確かめる。
- **古い SDK のままだと**、内側画面で全面にならず「見慣れた枠」で出るだけ（Apple）。何もしなくても壊れはしないが、Duo らしさはゼロ。
- **Pencil は発売時点で使えない**（Apple の注記「今年中」）。⑤はそれまで着手しない。
- **タブバーの位置**: Apple の資料は「操作は側面に寄る」と「タブバーは下のまま」の両方を言っていて、どちらになるか資料だけでは決められない。SDK の既定の動きを見てから決める。
- **費用**: §4 ①の自己申告の復習は AI を呼ばないので費用は増えない。⑤の日記の添削は増える（ロードマップ §2 のメモどおり上限の設計が要る）。

## 9. 「写真をページに貼る設計にすべきか」への答え

**変えない。** 理由:

1. 今のホームは、見た目は「無地にペタペタ」でも、**データはもう「1日＝1枚の台紙（ページ）」**になっている。1枚ごとの置き場所は
   台紙の幅に対する割合で保存している（`AlbumLayout`、`CollageBoard`）。だから台紙をそのまま**本の左ページに置ける**。
   置き場所・大きさ・回転は iPhone と Duo で同じ。
2. オーナーが今の見た目を気に入っている。iPhone（compact 幅）では**何も変えない**（1本の縦スクロールのまま）。
3. Apple の指針も「姿勢ごとに別の設計をするな。compact 幅と regular 幅の2つで考えろ」。Duo を開いた内側は regular 幅。
   そこだけ見開きにする。**iPad でこのアプリを開いた時も同じ見開きになる**（今は iPhone 専用アプリとして拡大表示されるので
   compact 幅のまま。iPad 対応に変えるかは別の決定）。

つまり「開いた時にページが開く」のほうを採る。「本のように貼る設計に作り直す」はしない。

## 10. 添削の設計（案。→ 2026-10-25 にオーナーが自分で決めた。§17-4）

赤ペン（本文の下に正しい文を赤で書く）は採用しない。理由（オーナー）: 設計が安っぽい。
加えて、ロードマップ §2 ④ にオーナー自身が書いている通り「**書き終わってから全部添削されると、読んで満足して覚えない**」。
赤ペンはまさにそれだった。ここでは「添削」を「書き終わった後の採点」ではなく「**書いている間の相棒**」として考え直す。

| 案 | 中身 | 良い所 | 弱い所 | 費用（AI） |
|---|---|---|---|---|
| **A. 一文ずつ、その場で** | 「。」「！」「？」を打つたびに、その一文だけを静かに確かめる。文末に小さな点: 灰（確認中）→ 緑（自然）／琥珀（もっと自然な言い方がある）。琥珀を押すと下からカードが出る: ネイティブの言い方（学習言語）、理由を一言（表示言語）、使った公式を青で。「この言い方にする」で**その文だけ**置き換え、「そのまま」で残す。本人の文は押さない限り変わらない | ロードマップ §2 ④ そのもの。小さく即時なので記憶に残る。赤も取り消し線も無い | 一文ごとに AI を呼ぶ。1日の上限の設計が要る。文の区切りが無い言語（中文は「。」で区切れるので可） | 文の数ぶん（短い入出力） |
| **B. 公式で書く** | 自由入力ではなく、その日の公式を選んで穴を埋める（「點＋一份＋鐵板麵」の「一份」を替える）。穴の中だけ AI が確かめる | 間違いが構造的に減る。アプリの「使い方①②③」と一体 | 自由に書けない。日記というより練習帳 | 少ない |
| **C. 問いに答える日記** | その日の写真から AI が問いを 1〜3 個作る（サーバの `getJournalPrompts` が既にある。今日の分だけ対応）。問いを押すと本文の上に引用で載り、本人は答えを 1〜2 文書く。答えごとに A の確かめ | 白紙の問題が消える。本人の「気持ち・思い出」が引き出される（§2 ②）。問い＋答えで1日の物語になる | 問いの生成に AI。質問に答えるだけだと「日記」の自由さが減る | 1日1回（問い）＋A |
| **D. 本文はそのまま、「レベルアップ」を横に** | 本人の文は一切触らない。横（Duo なら右ページの下、iPhone なら本文の下）に 2〜3 枚のカード: 「この文には今日の公式○○が使える」「ネイティブならこう言う」。押すと音声 | 否定が無い（PRODUCT.md「backlog を負債として見せない」と同じ姿勢）。本人の声が残る | 直す力は弱い | 1日1回 |
| **E. 今日の型 → 復習へ** | 書き終えたら「今日の型」として、使った・使うべきだった公式を 2〜3 個カードにし、「復習に入れる」で SRS の札にする（§2 ⑤） | 日記が復習とつながる。書きっぱなしにならない | サーバに新しい復習の形式が要る（`gradeReview`、Web と同じ次回日） | 1日1回 |

**おすすめ: C ＋ A を土台に、締めに E。** D は A の「そのまま」を選んだ時の表示として吸収できる。B は採らない（日記ではなくなる）。

Duo での見せ方（C＋A）: 左ページ＝その日の切り抜き（問いの元になった写真が、その問いを押すと少し光る）。右ページ＝問いと答え。
机に立てた姿勢なら、上＝切り抜きと問い、下＝キーボードと答え。

サーバに要る物: 一文を確かめる関数（`checkDiarySentence` のような物。入力＝その一文・前後の文・その日の語、出力＝自然か／言い換え／
理由／使った公式）、`getJournalPrompts` に日付を足す、1日の上限の鍵（`sentence_check`）。E は復習の形式の追加（Web と同じ採点）。

**決めてほしいこと**: A〜E のどれを採るか（おすすめは C＋A＋E）。決まったら、まず A だけを 1 本の PR で作る。

- **実機でのめくりの手触り**（指への追従、60fps が保てるか）。めくっている間だけ見開きを 1 枚の層にしてシェーダーで描くので、写真の多い日は重くなる可能性がある。
- **音**は合成したもので、実機で聞いていない。強すぎ・安っぽければ作り直す（スクリプトで数値を変えるだけ）。
- CI の見本は iPhone のシミュレーターに幅 1000×860pt の本を縮小して描いたもの。`spread-curl`／`spread-curl-late` はめくりの途中で止めた絵、
  `spread-turn` は自動で一度めくる録画、`spread` は表紙が開く連続写真。

## 17-4. 日記の「振り返る」と添削（オーナーが決めた設計）

| 指示 | 作った物 |
|---|---|
| 日記の右上に「振り返る」。その日のタイムライン（場所付き）をスクロールして確認 | `DiaryLookBack`: 時刻・場所（表示言語の地名）・捕まえた語。Duo では**左ページに出る**ので、右で書きながら左で読める。iPhone はシート |
| 習った語の公式は品詞ごとに色分け | 語を押すと、単語ページと同じ「使い方」のカード（例文の読みつき）を**品詞の色で**（`chunkPOSColorsOn`。単語ページの「品詞」の既定オフとは別） |
| 公式は押しても日記に貼れない | 公式のチップと、押すと本文に入る動きを外した。この日のことばを押すと「振り返る」がその語で開く |
| 使った公式は日記上でも品詞の色 | 組版（書いていない時）で、本文に書かれた公式を部品ごとの品詞の色に、語を青に |
| 書いている間に1文ずつ添削。間違った語・文法を指して直し、解説と一番自然な言い方 | 文を書き終える（。！？・改行）と、打つのが止まって 0.9 秒で、その1文だけをサーバへ（`checkDiarySentence`、速いモデル、同じ文は送り直さない）。本文の間違いに赤い点線、下に1文ずつのカード（間違い→直し・種類・解説、「一番自然な言い方」） |
| 書き終えて「添削する」→ 一番自然な全文、どんな間違いをしやすいか・したか・使うと自然なフレーズを、書いた状況に沿って解説 | `correctMyJournal` に書いている間の指摘を渡す（直した物も）。結果: 一番自然な全文（字ごとの読み）、講評、今日の間違い、間違えやすいところ、使うと自然なフレーズ |

- 費用: 1文ごとに AI を呼ぶ。1日の上限 `diary_sentence` 200 回（匿名 10）、書き終えの添削は今の `correction`（100 回）。
  速いモデルの短い入出力なので1回は小さいが、**毎日書く人が増えるほど増える**。`ai_call_log` の `journal_sentence` で見られる。
- **リアルタイムの意味**: 1文を書き終えた時に見る（1字ごとには呼ばない）。1字ごとは費用が文の長さ倍になり、書きかけの文に
  間違いを出すと邪魔になるため。
- サーバは **main に入るまで本番に出ない**。それまで iOS の1文の添削は理由の一行を出して止まる（書くことは止めない）。

## 17-6. Duo の他の画面

| 画面 | 開いた時（内側） | 直角に折った時（机に立てる） |
|---|---|---|
| カメラ | ファインダーを内側の画面の比率いっぱいに、操作は端の列 | 上＝ファインダー、下＝シャッターと操作 |

| 復習 | 左＝撮った写真、右＝4択 | 上＝写真、下＝4択 |

- **開いた時**の形は、幅の区分（regular）で作れる。第3段。
- **直角に折った時**は、今は作れない。理由: (1) アプリが**縦向きだけ**（Duo を横にして折ると画面は横向き）。横向きを許すと全画面に
  影響する（§7）。(2) 折った角度（`onHingeChange`）と折り目の位置（`reservedRegions`）は **iOS 27.1 SDK（Xcode 27.1）** の部品で、
  CI の Mac には Xcode 26.6 までしか無い（§12）。Xcode 27.1 が CI に来たら、横向きを Duo の内側だけに許し（regular 幅の時だけ）、
  折り目が横の時に上下に分ける。それまでは設計だけ（試作の「Duo 90°」で見た目を確かめられる）。
