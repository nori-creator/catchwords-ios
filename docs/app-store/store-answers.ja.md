# App Store Connect の質問への答え（2026-10-25 の版: 1.0.4 = 広告・自前のサーバ）

App Store Connect の画面で入れる項目の答え。根拠はこのリポジトリのコード（`ios/`）と Web 版（`nori-creator/Lovable-catch-words-app`）。
いま App Store Connect に入っている値は `App Store status` ワークフローの報告（ci-previews の `runs/store-status/status.md`）で確かめられる。

---

## 1. 年齢区分（App 情報 → 年齢区分）

2026-01-31 から新しい質問になった（Apple: Upcoming requirements）。**1.0.4 から「広告」だけ「はい」、ほかは全部「なし」／「いいえ」**（2026-10-11 の報告では全部「なし」で 4+）。

| 質問 | 答え | 理由 |
|---|---|---|
| ペアレンタルコントロール | いいえ | 無い |
| 年齢の確認（Age Assurance） | いいえ | 無い |
| 無制限の Web アクセス | いいえ | アプリの中で自由に Web を見る機能は無い（規約などはアプリの外の Safari で開く。ログインはシステムのログイン画面） |
| ユーザー生成コンテンツ | いいえ | 写真・メモは本人だけが見る。ほかの利用者に配る機能は無い |
| ソーシャルメディア | いいえ | 無い（友達の機能は後回し） |
| メッセージとチャット | いいえ | 無い |
| 広告 | **はい**（1.0.4 から） | 撮影の回数を使い切った時に、選んだ人だけ見る動画広告（AdMob のリワード広告）。PR #2 |
| 成人向けのテーマ・医療・性的表現・暴力・ギャンブル・コンテスト・ルートボックス | すべて「なし」 | 該当なし |

※ 友達の機能や、利用者どうしで写真を見せ合う機能を足したら「ユーザー生成コンテンツ」「ソーシャルメディア」が「はい」になり、通報・ブロックの仕組みが必須になる（審査基準 1.2）。

## 2. App のプライバシー（App プライバシー）

「データを収集しますか」→ **はい**。トラッキング → **いいえ**（広告の識別子 IDFA を使わず、App Tracking Transparency の許可も求めないため。「はい」にすると ATT の許可画面が必須になり、無いと差し戻される）。
下の表の上半分（当社のサーバが受け取るもの）は「ユーザーに関連付けられる」。`ios/CatchWords/PrivacyInfo.xcprivacy` と同じ内容にする（変える時は両方そろえる）。
広告の分（下の「広告で増えるもの」）は Google Mobile Ads SDK が集める。SDK 自身のプライバシーマニフェストが Xcode の報告にまとめて入るので、アプリの xcprivacy には書かない。

| 種類 | 収集 | 用途 | 何のことか |
|---|---|---|---|
| 連絡先情報 → メールアドレス | はい | アプリの機能 | ログイン |
| 連絡先情報 → 名前 | はい | アプリの機能 | 表示名（入れた人だけ） |
| ID → ユーザー ID | はい | アプリの機能・分析 | アカウントの番号。開発者の利用者画面・指標 |
| 位置情報 → 正確な位置情報 | はい | アプリの機能 | 撮った場所（許可した人だけ）。地名と地図、場所のリマインド |
| ユーザーコンテンツ → 写真またはビデオ | はい | アプリの機能 | 撮った写真と切り抜き |
| ユーザーコンテンツ → その他のユーザーコンテンツ | はい | アプリの機能 | メモ・学習の記録・入力した単語 |
| 検索履歴 | はい | アプリの機能・分析 | 「違う単語を入力」で調べた言葉、撮影で見つかった単語の記録 |
| 使用状況データ → 製品の操作 | はい | アプリの機能・分析 | AI の利用回数（1日の上限）、どの候補を選んだか（順位だけ） |
| 購入 → 購入履歴 | はい | アプリの機能・分析 | Web 版の Pro の状態をアカウントに持つ（iPhone アプリには課金なし） |
| ユーザーコンテンツ → 音声データ | いいえ | — | 声で調べる機能は今の版に無い |
| 診断 → クラッシュデータ | はい（**ユーザーに関連付けられない**） | アプリの機能 | Sentry（2026-10-27〜）: アプリが落ちた記録。機種・iOS・アプリの版と、落ちる前の操作の流れ。アカウント・メール・IP・写真・画面の撮影は送らない |
| 診断 → その他の診断データ | はい（**ユーザーに関連付けられない**） | アプリの機能 | Sentry: 保存の失敗・サーバの 500 番台の返事・読めなかった返事・サインインの失敗 |

**広告で増えるもの（1.0.4 から。Google の「App store data disclosure」の一覧による）**: どれも「ユーザーに関連付けられない」「トラッキング: いいえ」。

| 種類 | 用途 | 何のことか |
|---|---|---|
| 位置情報 → おおよその位置情報 | 他社の広告・分析 | IP アドレスからのおおよその場所 |
| ID → デバイス ID | 他社の広告・分析 | 端末の識別子（IDFA は使わない） |
| 使用状況データ → 製品の操作 | （上の行に）他社の広告・分析 を足す | 広告を見た・押したの記録 |
| 使用状況データ → 広告データ | 他社の広告・分析 | 表示した広告の記録 |
| 診断 → クラッシュデータ | （上の行に）分析 を足す | SDK の不具合の記録 |
| 診断 → パフォーマンスデータ | 分析・他社の広告 | 起動の時間など |
| 診断 → その他の診断データ | （上の行に）分析 を足す | SDK の動作の記録 |

- 「製品の操作」は当社の分と同じ項目なので、1 つの項目に用途を足す（Apple の画面は種類ごとに 1 つ。関連付けは「はい」のまま）。

- **第三者の AI に送ること**は、App のプライバシーの表では「収集」に含まれる（当社のサーバが受け取って処理するため）。別に、アプリの中の同意画面と、プライバシーポリシー（送り先の会社と国）で示している（審査基準 5.1.2(i)）。
- 2026-10-03 の表から変えた所: 「日記」と「声で調べる」が iPhone から無くなったので説明だけ直した（答えは同じ）。

## 3. 配信する国・地域（価格と配信状況）

2026-10-11 の朝は **175 の国・地域**（中国本土 CHN を含む）。同じ日の夕方に Rork が中国本土を外し、**174 の国・地域**になった（`App Store status` で確かめた）。EU は**事業者として申告して配信する**と決めた（申告はオーナー）。

- **中国本土は外した**（理由）: 中国本土で配信するには、政府への届け出番号（ICP 備案）を App Store Connect に入れる必要があり、生成 AI の機能には中国の許可も要る。アプリが使う Google の AI は中国本土からは使えないので、どのみち動かない。
- **EU の国々（デジタルサービス法 = DSA）**: App Store Connect で「事業者（trader）かどうか」の申告が要る（Apple: Manage European Union Digital Services Act trader requirements）。
  - **EU で配信しない場合も、申告そのものは要る**（Apple のページにそう書いてある）。
  - 事業者として申告すると、**住所（または私書箱）・電話番号・メール**が、EU の App Store のページに公開される。
  - 事業者ではない、と申告することもできる。その場合、EU の利用者には「消費者保護の法律による権利は適用されない」と表示される。
  - 事業者かどうかの判断材料（Apple の例）: アプリで収入を得ているか（アプリ内課金・有料・広告）、商品やサービスを宣伝しているか、消費税（VAT）の登録、仕事として作っているか。この iPhone アプリは無料・課金なし・広告なし。ただし Web 版で有料の Pro を売っていて、特定商取引法の表示もしているので、事業者に当たる可能性がある。迷ったら専門家に聞く（Apple も法的な助言ではないと書いている）。
  - 申告の場所: App Store Connect → 上の「ビジネス」→「契約」のタブ → 下の「コンプライアンス」→「デジタルサービス法」の「コンプライアンス要件を完了」（アカウント保有者か管理者だけ）。アプリごとの設定は「App 情報」→「App Store の規制と許可」→「デジタルサービス法」。画面の日本語の名前は少し違うことがある。
  - 2025-02-17 からは、確認済みの事業者の情報が無いアプリは、EU の App Store から外されている（Apple のお知らせ）。
- **台湾（TWN）は残す**: 台湾に住む日本語・英語の人（台湾華語を学ぶ人）が一番の対象。
- それ以外の国はこのままでよい（年齢区分・言語の制限は無い）。
- 変える場所: App Store Connect → アプリ → 価格と配信状況 → 配信状況 → 国または地域の配信状況を編集。

## 5. スクリーンショット

- 2026-10-11 の報告: 日本語に 6.9 インチ（APP_IPHONE_67）が 6 枚。**古い版の画面**（本棚・撮影の 3 つのモード・空の図鑑など、今は無い画面）なので、**今の版の画面に差し替える**。古い画面のままだと、審査基準 2.3（説明と画面がアプリと合っていること）で指摘されることがある。
- 必要な大きさ（Apple: Screenshot specifications）:
  - **6.1/6.3 インチ（Dynamic Island の中くらいの画面）: 1179×2556 または 1206×2622** — 必須
  - **6.9 インチ: 1320×2868・1290×2796・1260×2736**（無ければ 6.5 インチ 1284×2778・1242×2688 が必須）
  - 1 枚以上、10 枚まで。PNG か JPEG。透明部分のない画像。
- 撮る画面（5〜6 枚）: ①物の上に単語のタグが出た画面 ②単語をタップした後（ステッカーと単語）③図鑑 ④単語のページ ⑤復習 ⑥ホーム（日付ごとのアルバム）。PR #23 で図鑑とホームの見た目が変わるので、PR #23 が入ったビルドで撮る
- 実際の写真で撮った画面が一番よい（審査用アカウントに本物の写真で単語を集めてから撮る）。
- 撮り方: iPhone でサイドボタンと音量を上げるボタンを同時に押す。写真アプリに PNG で保存される。どの iPhone で撮ってもよい。
- 大きさをそろえる: 撮った画像を Claude に送れば、`scripts/store_screenshots.py` で 6.3 インチ（1206×2622）と 6.9 インチ（1320×2868）の両方にして返す（縦横比はほぼ同じなので、数ピクセル切るだけ。中身は変えない）。
- 入れる場所: App Store Connect → アプリ → 1.0.0 → 「iPhone」のスクリーンショット欄に、6.9 インチ用と 6.3 インチ用をそれぞれドラッグする（古い 6 枚は消す）。
- 日本語の画面だけ入れれば、英語のページにも同じ画像が出る（主言語が日本語のため。言語ごとの画像は任意）。
- **おすすめ**: 英語のページ（en-US）用に、表示を English にして同じ画面を撮り、英語の欄に入れる。入れないと、英語のページに日本語の画面が出る。

## 6. 言語のページ（日本語・英語・繁体字中国語）

- 2026-10-11 の報告では、App Store Connect に **日本語（主言語）・英語（米国）・繁体字中国語** の 3 つのページがある。
- 不具合修正の PR #23 で、**どのアカウントも台湾華語を学び**、表示は日本語か英語だけになった（繁体字中国語の表示は、ログインの画面と、前から使っているアカウントにだけ残る）。繁体字のページを読む人（台湾・香港の人）は、台湾華語を学ぶ対象ではない。
- 今の繁体字のページの説明文は古い（「台灣華語・英語・日語に対応」）。**繁体字のページを消すことを勧める**（`ios/metadata` からは消した。`App Store metadata` ワークフローは繁体字のページに触らず、「ios/metadata に無い言語」として一覧に出すだけ）。
- 消し方（Apple: Localize app information → Delete a language）: App Store Connect → アプリ → 右上の主言語（日本語）を押す → 「ローカライズ済み（Localized）」の中の「繁体字中国語」にポインタを合わせる →「–」を押す。そのあと、版 1.0.0 の画面と「App 情報」の画面の両方で、右上の言語の一覧から繁体字が無くなったことを確かめる（片方に残っていたら、そちらの画面でも同じように消す）。
- 消した後、繁体字の設定の人には主言語（日本語）のページが出る（Apple の説明）。
- App Store の「言語」の欄（アプリが対応する言語）は、アプリの中身から自動で決まり、繁体字中国語も出る。ログインの画面と許可の説明は繁体字に訳してあるので、間違いではない。
- 主言語を英語に変えると、日本語・英語以外の国でも英語のページが出るようになる。ただし主言語を変えられるのは、その言語のページが一度審査に通った後（Apple の条件）。1.0.0 では変えられないので、次の版以降に考える。
