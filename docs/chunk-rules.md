# 使い方チャンク（型）の表示ルール

使い方チャンクは「**ネイティブがその単語を使うとき、いちばんよく口にする形**」を、覚えやすい**公式**として見せる欄です。
2026-10-23 からは「使い方」の項目（旧「使い方パターン」）の中で、**場面の一言 → 公式 → その公式を使った例文** を1つの塊（パターン）として、
よく使う順に見せる（C17）。公式は四角と ＋ をやめて1つの句として読む（C18）。入れ替えられる所は入れ替えて練習できるようにします。

- 判定の実装：iOS `ios/CatchWords/Utilities/ChunkRules.swift`（形・入れ替え・訳の差し替え）、`LanguageRules.mentionsHeadword`（学ぶ語が入っているか）
- 表示：iOS `Views/ChunkLineView.swift`（公式の行）、`Views/PatternsCard.swift`（パターンのカード: 場面・公式・例文・ポイント）
- パターンの生成と門：Web `src/lib/usage-patterns.ts`（指示文 `usagePatternsRule`、門 `gateUsagePatterns`、今までの欄への写し）
- Web：作る指示 `src/lib/ai.functions.ts`（`formulaChunkRule` / `specificChunkRule`）、表示前の整形 `src/lib/chunk-grammar.ts`、`src/lib/extras.ts`（`refineUsageChunks`）
- 試験：`ios/LanguageRules/cases.json`（`tidyChunk` / `swapTranslation` / `mentionsHeadword` / `brokenChunk`）。CI が毎回走らせる

## ルール

| # | ルール | 守る場所 |
|---|---|---|
| C1 | **どの型にも学ぶ語そのもの**（日本語・英語は活用形も可）を1つの四角として入れる。「芒果」の型に「很+甜」だけを出さない | 指示文、`mentionsHeadword`（表示で落とす） |
| C2 | **学ぶ語の四角は固定**。太い縁で強く見せ、入れ替え（スクロール）させない | `isSwappable`、指示文「slot:false・alts なし」 |
| C3 | ネイティブが**実際にいちばん高い頻度で**使う形を、頻度の高い順に厳選する（詳細は5つまで、復習の答えは3つまで） | 指示文、表示の件数 |
| C4 | **公式の形**：語ごとの四角を ＋ でつなぐ。入れ替える所にも「人」「事」「someone」と書かず、ネイティブがいちばんよく入れる**具体語を1つ**入れる（跟＋男朋友＋吵架） | 指示文、`ChunkLineView` |
| C5 | **入れ替えられる所（点線と ▾）は、同じ公式のまま1語を替えると意味・場面が変わる所だけ**（馬桶＋[塞住了/不通/壞了]、[開/關/吹]＋電風扇、膝蓋＋[痛/破皮/瘀青]）。品詞は問わない。**程度の語（很・超・非常・有點）は入れ替えにしない**（オーナー 2026-10-23「入れ替え可能が很とか程度を表すものがほとんどになってる」— CH11 の改正を戻す）。別の場面になる語は候補に入れず、別のパターンにする | `isSwappable`、Web `tidyForStorage`、指示文 |
| C6 | 入れ替える所の候補は、ネイティブがそこに**実際によく入れる具体語**を頻度順に3〜6個、それぞれ**読む人の言語の訳**付き。どれを入れても型ぜんぶが自然に言える語だけ。候補の無い所は点線にしない | 指示文、`isSwappable`、`ReaderLanguage.scrub`（訳の言語） |
| C7 | **1語として使われる語は分けない**（芒果冰・芒果乾・台灣芒果は1つの四角）。台湾華語で、学ぶ語と隣り合った名詞（記号 N）どうしは1つにまとめる。まとめて四角が1つになった型は「語」なので型として出さない（関連語の欄に入る）。札1つで保存された古い型は消さない | `mergeCompounds`、`isPattern`、指示文 |
| C8 | 型ぜんぶが**文法的に正しく、ネイティブがそのまま言う形**。台湾華語の「名詞＋形容詞」には程度の語を補う（滷味＋很＋入味）。**補った程度の語は固定（入れ替えない）**（オーナー 2026-10-25「程度は入れ替え不可で很で固定」— サーバの `withFixedDegree` も AI が付けた slot・alts を外す） | `withDegree`、`withFixedDegree`、指示文 |
| C9 | **短く**：公式であって文ではない（オーナー 2026-10-23）。2〜3パーツが基本、台湾華語は中身8字・中身4パーツ（**把・被 と名詞の後ろの 裡・上 などの方位の語は数えない**、全部で6パーツまで — 2026-10-30、CH17）、英語は4語、日本語は12字まで。**長さに収めるために自然な句を削らない**（削らないと入らない型は出さない）。主語・語気助詞・句点・感嘆符・疑問符を入れない。文は例文が受け持つ | 表示の `tooLong`、指示文 |
| C10 | **量詞を含めない**（量詞の欄と重ねない） | 表示、指示文 |
| C11 | **どの語にも付く組み合わせ**（買・喜歡・這個 だけを足した型）は出さない | Web `generic-chunks.ts`、指示文 |
| C12 | 訳は**訳だけ**（説明・括弧書きなし）、読む人の言語で。語を入れ替えたら、訳の中の元の語の部分を入れ替えた語の訳に差し替える。見つからない時は「（很 → 非常: 非常に）」と何を替えたかを添える | `swappedTranslation`、`ReaderLanguage.scrub` |
| C13 | **操作**：四角を押す → その語の発音。点線の四角を押す → その語の発音と、候補の輪（縦にスクロール）。輪で選ぶ → その語の発音、型と訳が入れ替わる。右端のボタン → 入れ替えた後の型ぜんぶの発音 | `ChunkLineView` |
| C14 | **区切りの記号を四角にしない**。記号だけの四角（+ ＋ ・ / ／ |、空白）は落とし、「牛蒡+炒」は + で切って別の四角にする。英字・数字に付いた + は語の一部（C++） | `withoutSeparatorParts`（`tidy` の最初）、Web `chunk-grammar.ts`、指示文 |
| C15 | **崩れた型を出さない**。台湾華語で「学ぶ名詞＋裸の他動詞（1〜2字・結果やアスペクトの字で終わらない）」だけの型（嘴邊肉＋切）と、学ぶ語を写しただけの訳（嘴邊肉をする）を落とす | `isBroken`、Web `isBrokenUsageChunk`、指示文 |
| C16 | **iOS の候補ホイールを含む親ビューには Metal の layerEffect をかけない**。元の Picker と語・訳の行を保ち、作り直し中もネイティブの候補を表示する | `SectionCard.supportsLayerEffects` / `patternCard` |
| C17 | **パターン = 場面の一言 ＋ 公式 ＋ その公式を使った例文**を1つの塊として、ネイティブがよく使う順に2〜4個（1つしか無ければ1つ。数を揃えない）。場面の一言は**その公式を使う一般的な状況だけ**（「トイレが詰まった・流れない時」「トイレを使った後」）— 例文の文脈・相手・気持ち（✗「家の掃除の分担を話す時」✗「困って」）は書かない。種類（動作 / 状態・トラブル / 言い回し）はデータ（`kind`）にだけ持ち、画面に出さない。保存済みの語は作り直さない（↻ を押した語だけ）が、**見た目は同じ**: 古い語（`usage_patterns` 無し）は公式ごとに、それを含む例文と組にして同じ塊で出す（`ChunkRules.patternsFromLegacy`。含む例文の無い公式、どの公式にも当たらない例文は単独の塊。捨てない）。塊には **①②③** の番号（よく使う順 = サーバの `share` 順）。見出しは「使い方」（2026-10-23 夜、他の見出しと揃えた名詞） | Web `usagePatternsRule` / `gateUsagePatterns`、iOS `PatternsCardContent` |
| C18 | **公式は1つの句として読む**：四角も ＋ も無し。学ぶ語は青い字だけ（背景の印は付けない）、**一緒に使う語（相手）は黒の太字**（覚える物）、つなぎの語（很・的・把・介詞・助詞）は灰色。訳の中の相手の語の訳も太く。品詞の色は既定でオフ、カードの「品詞」で切り替え（オンでも**学ぶ語は青のまま**、動詞の赤は鮮やかな `#FF3B30`。2026-10-23 夜）（端末が覚える） | `ChunkRules.role` / `partnerGlosses`、`ChunkLineView`、`chunk.posColors` |
| C19 | **例文は公式を含む**（入れ替えの候補に替えた形でも可）。例文の中の公式に当たる所は青の太字（下線は引かない）。例文は**一人称の発話**（説明文・看板・地の文・その語をネイティブが使わない場面の文は不可）。**語の途中で折り返さない**（`example.chunks` の語ごとに WORD JOINER） | Web `chunkInSentence`、iOS `ChunkRules.spanText` / `SentenceRuby(span:words:)` / `Sentences.unbreakable` |
| C20 | **汎用の相手は後回し**：吃/喝/拿/買/看/做/用 だけを足した型、名詞＋很＋好/好吃/好喝/甜/大/貴/漂亮 は、強い型が2つ以上あれば落とし、無ければ最後に残す（2026-08-28「喝珍珠奶茶 は残す」の緩和）。指示文の見本から 芒果＋很＋甜 を外す | Web `WEAK_PARTNERS` / `isWeakPartnerChunk`、`target-profile.ts formulaExample` |
| C21 | **型ごとに「ひと言解説」**（`usage_chunks[].note`、読む人の言語で1文・40字ほど）: その型のニュアンス・使う場面・似た言い方との違い・間違えやすい所のうち1つ。型の訳の言い直し・一般論は書かない。画面では電球を押すと出る。古い語には無い（電球を出さない）（オーナー 2026-10-24） | `chunkNoteRule`、`tidyForStorage`、`scrubExtrasForReader` |
| C22 | **弱い相手**（吃/喝/拿/看/用/做＋見出し語、見出し語＋很＋好/好吃/好喝/甜/大/貴/漂亮…）は、強い型が2つ以上ある語では落とし、無ければ最後へ回す。指示文でも禁じ、その物専用の動詞（吹＋電風扇、沖＋馬桶、剝＋椪柑、搭＋手扶梯）を優先させる（オーナー 2026-10-24、貼られた分析「汎用すぎるチャンク」） | `WEAK_PARTNERS`・`isWeakPartnerChunk`、`gateUsageChunks`、指示文 |
| C23 | **例文は一人称のセリフで、同じ返事の型を1つ字のまま含める**（説明文・看板・アナウンス・地の文・その語を使わない場面の文は禁止）。**句読点を除いて 12〜24字**（画面で2行・16pt 以上に入る長さ、2026-10-25）。門は 24字以内の文があれば長い文を使わず、型を含む文を先にする。ひと言解説は訳の言い直し・80字超を保存しない | `examplePatternsRule`（先頭に絶対ルール a〜e）、`pickExamplePatterns`、`tidyForStorage` |
| C25 | **速い AI でも守れるよう、型と例文の指示の先頭に短い「絶対ルール」**（型 9つ・例文 4つ、良い例・悪い例つき）を置く。長い説明の前に、破ったら返さない項目だけを並べる | `chunkHardRules`、`examplePatternsRule` |
| C27 | **在＋場所の名詞の後ろには 裡・上・中 を別の札で付ける**（放進・收進＋容器 もふつう付ける）。見出し語と方位の語が1つの札（筆袋裡）で来たら分ける。表示でも方位の語を前の名詞とまとめない。容器・場所の名詞では「把＋物＋放進＋容器＋裡」のような入れる・置く型を汎用とみなさない（2026-10-30、CH17） | `chunkHardRules` 3、`splitHeadwordLocative`、iOS `ChunkRules.isLocative` |
| C28 | **間違いは台帳に1行足す**（`server/src/lib/chunk-cases.ts`）。1行が、門（✗ の型を落とす）・指示文（原因の種類ごとの教訓と、その語の ✗ / ○）・試験（○ は落ちない、✗ は必ず落ちる）の3つに同時に効く。○ は台湾華語の話者が確かめた物だけ指示文に出す（`checked`） | `chunk-cases.ts`、`chunkCasesRule`、`chunk-cases.test.ts` |
| C24 | **関連語に短い訳**（`related_words[].gloss`、読む人の言語で1語〜数語）。画面では語の右に出し、違いの解説（note）はその下 | 指示文、`scrubExtrasForReader` |
| C26 | **例文の中身は、その場面で台湾の人がいちばん自然に・よく言う実用的な文**。実在の名前（店・チェーン・場所・駅・行事・歴史や文化・毎年のように起きる出来事）は、ネイティブが実際にその名前で言うのが最も自然・よくある時だけ入れる（○ 便當「我去7-11買個便當」/ 月餅「中秋節快到了，要買月餅嗎？」）。ふつう言わない所に名前・出来事を足さない（✗ 雨傘「我在信義區新光三越買了雨傘」）。名前は実在して正しい物だけ、実在の人について事実でない事を書かない、日付で変わる最近のニュース・値段は書かない（オーナー 2026-10-25） | `REAL_NAMES_RULE`（例文の絶対ルール e）、`examplePatternsRule` |

## チャンクの不具合が起きたときの手順（毎回必ず）

1. **下の事故表を全部読み直す**。同じ根を持つ事故が過去にないかを確かめる。
2. 事故表に1行足す（何が起きたか・なぜ起きたか・どのルールで止めるか）。**間違いの型と正しい型を `server/src/lib/chunk-cases.ts` の台帳に1行足す**（C28。門・指示文・試験に同時に効く）。
3. **ルールを改正する**。穴になっていたルールを書き直すか、新しいルールを足す。前の事故のルールと矛盾しないかを確かめる（例: CH7 で「副詞は点線にしない」としたが、CH11 で程度の語だけは入れ替え可能に改正した）。
4. `ios/LanguageRules/cases.json` に、その事故を再現する試験を足す（直す前に落ち、直した後に通るもの）。
5. **iOS の表示と Web の指示文・表示の両方**を直す。片方だけ直すと、もう片方から同じ型が出続ける。
