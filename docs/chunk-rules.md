# 使い方チャンク v2（2026-10-30 — 一から設計し直した版）

オーナー 2026-10-30「今までのチャンクのプロンプトや指示は全てを忘れて…1から設計し直して」「ネイティブが頻繁に使い自然なフレーズを
ユーザーに早く正確に表示したい。アウトプットを書く時や話す時にその塊として認識できるようにさせたい」。
下の「v1」の節（C1〜C26・事故表）は、**古い語（`usage_chunks`）の表示のため**に残す。新しい語は v2（`usage_chunks_v2`）。

## 定義（1つだけ）

**チャンク = その名詞を使ってネイティブが実際に口にする一文の中の、名詞を含む最小の「そのまま言える塊」。**

- 必ずネイティブの一文から切り出す（文 → 塊の順。塊を先に考えさせると作文になり「裝進＋筆袋」のような切れ端になる）。
- 見出し語は名詞だけ（撮った物）で、**決して入れ替えない**（入れ替えたら解説の意味が無い）。入れ替えは名詞 1 か所まで、候補 3〜6。
- 長さの字数の上限は置かない。制約は「一息で言える」と「画面の 1 行に入る」だけ。
- 塊の区切り（block）はネイティブが一息に言う単位（筆袋裡・半糖少冰 は 1 つ）。見出し語の青は**字の範囲**で塗る（`head`）。
- 量詞の型・見出し語だけ・主語付きの文は塊ではない。

## 型 = 名詞の役割（`CHUNK_PATTERNS`。2026-10-30 夜に見直し）

オーナー「本当にこの 10 種で全部網羅できる？ 名詞裡とか気になる」→ 前の一覧は「よく出る形」の寄せ集めで、介詞が 用・在・把 だけ、
方位の語が 裡 だけ、名詞が主語になる動作（蚊子咬我）や 跟/給/從 の句が無かった。**名詞が文の中で立てる場所は文法で決まっている**
ので、その役割で分ける。これは AI に「名詞が立てる場所」を全部思い出させるための一覧で、門ではない（合否は 2 社の一致）。
どれにも当てはまらない塊は `other` として捨てない。

| 役割 | 形 | 例 |
|---|---|---|
| object — 動詞の目的語 | 動詞＋名詞（了/過・一下・補語が付く形も） | 吹電風扇 / 買到票 / 洗一下杯子 |
| subject — 主語・話題 | 名詞＋動詞了 / 名詞＋被＋動詞了 / 名詞＋很＋形容詞 / 名詞＋比＋名詞＋形容詞 / 名詞＋動詞＋目的語 | 手機沒電了 / 湯很燙 / 蚊子咬我 |
| coverb — 介詞の目的語 | 在/到/從/往・用/拿・跟/和・給/對/幫/替・把・被 ＋名詞（＋方位）＋動詞 | 用吸管喝 / 跟朋友吃飯 / 從冰箱裡拿出來 / 把衣服放進洗衣機裡 |
| modified — 修飾される側 | 形容詞(的)＋名詞 / 動詞(的)＋名詞 / 名詞(的)＋名詞 | 冰的紅茶 / 剛買的手機 / 台灣的芒果 |
| modifier — 別の名詞を修飾 | 名詞的名詞 / 名詞＋名詞 / 名詞＋和＋名詞 | 雨傘的把手 / 手機殼 / 筷子和湯匙 |
| locative — 場所として | 名詞＋裡/裡面/上/上面/下/底下/外/外面/中/旁邊/前面/後面 を含む句 | 放在桌上 / 冰箱裡的牛奶 / 門口旁邊 |
| set_phrase — 決まった言い回し | 注文・依頼・質問・感嘆 | 紅茶半糖少冰 / 幫我拿一下遙控器 / 有沒有衛生紙 |
| other | 上のどれでもないが、ネイティブが塊として言う物 | — |

AI は語ごとに頻度の高い物を 3〜5 個返し、照合で 2〜4 個に絞る。「買・有・喜歡・這個」だけを足した形は、目標 3 級以上の読者には
読む時の並べ替えで後ろへ（`orderForReader`）。目標 1・2 級の人への簡単な動詞の型（吃＋小籠包）は object として普通に出る（10-26 の決定）。

## 作る流れ（`chunks-v2.server.ts`。2026-10-30 の採点 3 回を経た形）

```
撮る → [書庫に有る?] ─yes→ 即表示（別の表示言語なら訳だけ小さく書かせる）
          │no
          ├─ 書く A（Gemini）  ┐ 並列、同じ指示文（文 → 塊、中国語だけ・軽い形: sentence / text / key / pattern / slot / alts）
          └─ 書く B（Claude）  ┘
                 ↓ 形だけの門（gateChunksV2: 見出し語・文の部分文字列・句読点・文 24 字・見出し語の直前の量詞・入れ替えの字と候補・重複）
             照合（mergeByAgreement）: ①同じ型（入れ替えの所を ＿）②含む関係（長い方）③**同じ中心の語 key**（關掉電風扇 と 把電風扇關掉）
                 ↓
             審査（judgeV2Prompt）: 候補を**全部まとめて 2 社に**見せ、1 つずつ natural と「よく言う順」
             決める（rankAndSelect）: A の塊は B の審査、B の塊は A の審査（逆の会社の審査が無ければ自分の会社の審査）、
               一致した塊はどちらかが natural なら通す。並びは 2 社の順位の平均。同じ key・同じ型は 1 つ。上限 4。
                 ↓
             仕上げ（finishV2Prompt）: 残った塊にだけ block（一息の単位）・品詞・読む人の言語の訳・解説
                 ↓
             書庫 chunk_library（中国語は表示言語をまたいで共有。不自然と落ちた物も rejected で残す） + chunk_library_text（訳は言語ごと）
```

- **速さの要は「考えさせない」**: 3 回目までの採点で 1 社 27〜40 秒かかった原因は、モデルが既定で長く考えていた事。計測
  （`chunks-v2.probe.test.ts`、Actions の mode=probe、2026-10-30）: Gemini 3.8 Flash は既定 22.3 秒 → `reasoningEffort: low` 4.4 秒
  （minimal は 400 で断られる、none 4.8 秒、thinking_budget 0 4.4 秒）。Claude Haiku 5.5 は既定 24.9 秒（考えた分 5,340 トークン）→
  `thinking: disabled` 1.9 秒。`askJson` が `speedOptions` でこれを足す。**SDK（openai-compatible）は生の `reasoning_effort` を自分の欄で
  上書きして消す**ので、SDK の欄 `reasoningEffort` で渡す。書く段の返事も軽くした（block・品詞・訳は仕上げの段）。
  5 回目の採点（8 語）: 1 語 p50 11.4 秒（書く段 p50 3.8 秒、審査 2.9 秒、仕上げ 3.8 秒）、時間切れ 0、塊 0 の語 0。
- **塊の字は文に合わせて直す**（`repairChunkText`、形だけ）: 考えさせない設定の AI は、字を少し変えて切る（開電風扇 ← 你去開一下電風扇）か
  見出し語を外して切る（借我撐一下 ← 雨傘借我撐一下）ことが多い（1 社の返事の 2〜5 割）。文の中でその字が順に入る最短の範囲
  （余分 4 字まで）・隣の見出し語まで広げた範囲に直す。直せなければ落とす。
- **同じ言い方は審査にまとめさせる**（`same`）: 把雨衣穿起來 と 把雨衣穿上、紙箱濕掉了 と 紙箱被雨淋濕了 は中心の語が違うので
  `key` では重ならない。審査が「前の候補と同じ事を言っている」と番号を付け、順位の良い方だけ残す（把窗簾拉上 と 拉開 は別）。
- **書き手・審査は上位のモデル、仕上げは速いモデル**（2026-10-30 の比べ、60 語）: Gemini 2.5 Pro × Claude Sonnet 5.5 は
  Flash × Haiku より基本的で頻度の高い塊を出した（滑手機・去剪頭髮・買便當・帶便當・忘記帶鑰匙 ↔ Flash は 盆栽的葉子怎麼都枯掉了・
  夾娃娃機一直吞我的錢 のように長く場面の狭い物が混ざる）。速さは同じくらい（p50 8.6 秒 vs 11.5 秒、考える量は最小）。語ごとに
  1 回だけ作って書庫で共有するので上位を使う（1 語 4〜5 セント、379 語で 15〜20 ドル）。区切り・品詞・訳の仕上げは Haiku（2 秒）。
- **読む人の言語の判定に `normalizeTargetLanguage` を使わない**（事前投入で発覚）: 知らない言語（es・ko・vi）を既定の zh-TW に落とすので、
  その読者が「訳は要らない」扱いになり、訳の行が書かれなかった。`readerIsTarget` は学ぶ言語の一覧に在る時だけ比べる。
- **審査は「自然か」だけ**（5 回目の採点で、審査に「どの物にも言える物は false」と書いたら 把馬克杯放進洗碗機裡・用馬克杯喝豆漿・
  把螢光筆放進筆袋裡面 のような普通の言い方まで false にされた）。その物らしさ・よく言うかは rank で後ろに回す。
- **一致は字ではなく中心の語**: 自由に書いた 2 社の文が字まで揃うことは稀（3 回目の採点で 7%）。「2 社が独立に同じ組み合わせ
  （帶＋雨傘、半糖去冰）を選んだ」事を頻度の証拠にする。字の違う 2 つは両方を審査に出し、順位で 1 つにする。
- **自然さをプログラムで判定しない。** v1 の門にあった汎用・弱い相手・意味の衝突・禁止一覧・分割・echo は v2 に持ち込まない
  （禁止を足すたびに正しい形を巻き添えにしてきた）。門が見る「形」は、見出し語の直前の量詞（量詞は別の欄）と、入れ替えの所の
  代名詞（名詞でない）まで。
- 「どの物にも言える文（多少錢・是誰的・在哪裡・借我一下）」は、書く段の指示と審査の両方で外す（3 回目の採点で 這個馬克杯多少錢・
  刷子借我用一下 が通った）。
- **帯（TOCFL のレベル）で分けない**（2026-10-30、オーナーが判断を委ねた）: ネイティブの頻度・自然さは学習者のレベルで変わらない。
  「1・2 級の語彙で」と書かせると教科書の文に寄る（自然さが第一の目標）。書庫が 1 組なので、1 人目の後は全員が待ち無し。
  読む時は、読む人の目標レベルで並べ替える（`orderForReader`: 目標 3 級以上には、汎用の動詞だけの塊を他に 2 つ以上あれば外す）。
- 図鑑の影の 379 語は出す前に書庫に入れる（`chunks-v2.seed.test.ts`、Actions の `chunks-v2.yml` の seed）。
- 採点: `chunks-v2.eval.test.ts`（60 語の `__fixtures__/chunks-v2-eval.json`。上位モデルで作った参照と比べる）。
  指示文・モデルを変える時は採点が下がらないことを確かめる。報告は「不自然と落ちた」と「省いた（重複・上限）」を分けて出す。

## 画面

- 1 行の句。見出し語の字だけ青。入れ替えの所は点線＋ホイール。1 行に入らない時は縮め、最小でも入らない塊は出さない。
- 例文はその塊を切り出した文（`sentence`）。番号は塊と同じ。
- 待ち: 他の項目は即表示、チャンクの欄は骨組み（文言なし）を先に出し、合格した塊が入る。締め切りで何も無ければ静かに閉じ、
  次に開いた時に出す（根拠: Nielsen の 1 s / 10 s、Maister「占有された時間・理由の分かる待ち」、Buell & Norton の労働の錯覚、
  レイアウトのずれの回避）。

## 間違いが出た時

1. 塊をそのまま `chunks-v2-eval.json` の語に足して採点し、2 社の返事（report.md）を見る。
2. 指示文の**定義や型の一覧**を直す（個別の ✗ の例を足さない）。採点が下がらないことを確かめてから出す。
3. 門に自然さの決まりを足さない。足すのは**形**の決まりだけ。

# v1（古い語の表示ルール — `usage_chunks`）

使い方チャンクは「**ネイティブがその単語を使うとき、いちばんよく口にする形**」を、覚えやすい**公式**として見せる欄です。
2026-10-23 からは「使い方」の項目（旧「使い方パターン」）の中で、**場面の一言 → 公式 → その公式を使った例文** を1つの塊（パターン）として、
よく使う順に見せる（C17）。公式は四角と ＋ をやめて1つの句として読む（C18）。入れ替えられる所は入れ替えて練習できるようにします。

- 判定の実装：iOS `ios/CatchWords/Utilities/ChunkRules.swift`（形・入れ替え・訳の差し替え）、`LanguageRules.mentionsHeadword`（学ぶ語が入っているか）
- 表示：iOS `Views/ChunkLineView.swift`（公式の行）、`Views/PatternsCard.swift`（パターンのカード: 場面・公式・例文・ポイント）
- パターンの生成と門：Web `src/lib/usage-patterns.ts`（指示文 `usagePatternsRule`、門 `gateUsagePatterns`、今までの欄への写し）
- Web：作る指示 `src/lib/ai.functions.ts`（`formulaChunkRule` / `specificChunkRule`）、表示前の整形 `src/lib/chunk-grammar.ts`、`src/lib/extras.ts`（`refineUsageChunks`）
- 試験：`ios/LanguageRules/cases.json`（`tidyChunk` / `swapTranslation` / `mentionsHeadword` / `brokenChunk`）。CI が毎回走らせる

## ルール

| # | ルール | 守る場所 |
|---|---|---|
| C1 | **どの型にも学ぶ語そのもの**（日本語・英語は活用形も可）を1つの四角として入れる。「芒果」の型に「很+甜」だけを出さない | 指示文、`mentionsHeadword`（表示で落とす） |
| C2 | **学ぶ語の四角は固定**。太い縁で強く見せ、入れ替え（スクロール）させない | `isSwappable`、指示文「slot:false・alts なし」 |
| C3 | ネイティブが**実際にいちばん高い頻度で**使う形を、頻度の高い順に厳選する（詳細は5つまで、復習の答えは3つまで） | 指示文、表示の件数 |
| C4 | **公式の形**：語ごとの四角を ＋ でつなぐ。入れ替える所にも「人」「事」「someone」と書かず、ネイティブがいちばんよく入れる**具体語を1つ**入れる（跟＋男朋友＋吵架） | 指示文、`ChunkLineView` |
| C5 | **入れ替えられる所（点線と ▾）は、同じ公式のまま1語を替えると意味・場面が変わる所だけ**（馬桶＋[塞住了/不通/壞了]、[開/關/吹]＋電風扇、膝蓋＋[痛/破皮/瘀青]）。品詞は問わない。**程度の語（很・超・非常・有點）は入れ替えにしない**（オーナー 2026-10-23「入れ替え可能が很とか程度を表すものがほとんどになってる」— CH11 の改正を戻す）。別の場面になる語は候補に入れず、別のパターンにする | `isSwappable`、Web `tidyForStorage`、指示文 |
| C6 | 入れ替える所の候補は、ネイティブがそこに**実際によく入れる具体語**を頻度順に3〜6個、それぞれ**読む人の言語の訳**付き。どれを入れても型ぜんぶが自然に言える語だけ。候補の無い所は点線にしない | 指示文、`isSwappable`、`ReaderLanguage.scrub`（訳の言語） |
| C7 | **1語として使われる語は分けない**（芒果冰・芒果乾・台灣芒果は1つの四角）。台湾華語で、学ぶ語と隣り合った名詞（記号 N）どうしは1つにまとめる。まとめて四角が1つになった型は「語」なので型として出さない（関連語の欄に入る）。札1つで保存された古い型は消さない | `mergeCompounds`、`isPattern`、指示文 |
| C8 | 型ぜんぶが**文法的に正しく、ネイティブがそのまま言う形**。台湾華語の「名詞＋形容詞」には程度の語を補う（滷味＋很＋入味）。**補った程度の語は固定（入れ替えない）**（オーナー 2026-10-25「程度は入れ替え不可で很で固定」— サーバの `withFixedDegree` も AI が付けた slot・alts を外す） | `withDegree`、`withFixedDegree`、指示文 |
| C9 | **短く**：公式であって文ではない（オーナー 2026-10-23）。2〜3パーツが基本、台湾華語は8字・4パーツ、英語は4語、日本語は12字まで。主語・語気助詞・句点・感嘆符・疑問符を入れない。文は例文が受け持つ | 表示の `tooLong`、指示文 |
| C10 | **量詞を含めない**（量詞の欄と重ねない） | 表示、指示文 |
| C11 | **どの語にも付く組み合わせ**（買・喜歡・這個 だけを足した型）は出さない | Web `generic-chunks.ts`、指示文 |
| C12 | 訳は**訳だけ**（説明・括弧書きなし）、読む人の言語で。語を入れ替えたら、訳の中の元の語の部分を入れ替えた語の訳に差し替える。見つからない時は「（很 → 非常: 非常に）」と何を替えたかを添える | `swappedTranslation`、`ReaderLanguage.scrub` |
| C13 | **操作**：四角を押す → その語の発音。点線の四角を押す → その語の発音と、候補の輪（縦にスクロール）。輪で選ぶ → その語の発音、型と訳が入れ替わる。右端のボタン → 入れ替えた後の型ぜんぶの発音 | `ChunkLineView` |
| C14 | **区切りの記号を四角にしない**。記号だけの四角（+ ＋ ・ / ／ |、空白）は落とし、「牛蒡+炒」は + で切って別の四角にする。英字・数字に付いた + は語の一部（C++） | `withoutSeparatorParts`（`tidy` の最初）、Web `chunk-grammar.ts`、指示文 |
| C15 | **崩れた型を出さない**。台湾華語で「学ぶ名詞＋裸の他動詞（1〜2字・結果やアスペクトの字で終わらない）」だけの型（嘴邊肉＋切）と、学ぶ語を写しただけの訳（嘴邊肉をする）を落とす | `isBroken`、Web `isBrokenUsageChunk`、指示文 |

## チャンクの不具合が起きたときの手順（毎回必ず）

1. **下の事故表を全部読み直す**。同じ根を持つ事故が過去にないかを確かめる。
2. 事故表に1行足す（何が起きたか・なぜ起きたか・どのルールで止めるか）。
3. **ルールを改正する**。穴になっていたルールを書き直すか、新しいルールを足す。前の事故のルールと矛盾しないかを確かめる（例: CH7 で「副詞は点線にしない」としたが、CH11 で程度の語だけは入れ替え可能に改正した）。
4. `ios/LanguageRules/cases.json` に、その事故を再現する試験を足す（直す前に落ち、直した後に通るもの）。
5. **iOS の表示と Web の指示文・表示の両方**を直す。片方だけ直すと、もう片方から同じ型が出続ける。
