# 単語の中身を誰と共有するか（S1〜S8）

オーナー決定（2026-10-25）:

> 一つの単語について表示言語が同じで TOCFL のレベル（現状と目標）も同じくらいの場合、単語のすべての項目を共有して。
> ただ表示言語が同じで TOCFL のレベル1のユーザーとレベル5とかの人の例文、チャンク以外の項目は共有する。
> 表示言語が異なる場合は全く共有しない。完全に分ける。

同日に決めたこと:

- 「同じくらい」= **現状の帯と目標の帯が両方同じ**（TOCFL 1・2級 = 帯A、3・4級 = 帯B、5・6級 = 帯C。組は AA・AB・AC・BB・BC・CC など）。
- **保存した時の帯で固定**。後でレベルを変えても、保存済みの語の例文・チャンクは変わらない。↻ を押した語だけ、今の帯で作り直す。
- 見出し語の読み（注音・ピンイン）は辞書で決まる事実なので、言語をまたいで共有してよい。
- 語の TOCFL の級はアプリに出さない（消した）。表示に足し直さない。

## 規則

| # | 規則 | どこで |
|---|---|---|
| S1 | 単語の中身の置き場は2つ。**言語の置き場**（`word_explanations`、鍵は 表示言語 × 母語）と、**レベルの置き場**（`word_level_content`、鍵は 表示言語 × 母語 × 帯）。 | DB `20261025120000_level_content.sql` |
| S2 | **レベルで分ける項目は例文とチャンクだけ**: メインの例文と訳、場面の札、例文のパーツ、追加の例文、パターンの数、使い方チャンク（`LEVEL_EXTRAS_KEYS`）。ほかの項目（意味・量詞・関連語・台湾メモ・使う場面…）は言語の置き場。 | `server/src/lib/level-content.ts` |
| S3 | 帯の鍵は `"A>B"`（現状の帯 > 目標の帯）。現状の級が空なら目標の1つ下（`getUserLevels` と同じ）。 | `levelBandKey` |
| S4 | 札（`stickers.level_band`）に、**保存した時の帯**を書く。`legacy` = この決まりの前に保存した語。空 = まだ書いていない（読む時にその時の帯で書く）。同じ語の札が複数あれば、最も古い札の帯。 | `callerLevelBand`、`pinStickerBand` |
| S5 | `legacy` の札の語は、例文・チャンクを**今までどおり**に読む・書く（中身を作り直さない — 2026-10-23 の決定）。そのため、古い語のメインの例文は、ほかの言語の人と同じ文のことがある（その人の言語の訳・札は別）。↻ を押すと今の帯に移り、新しい分け方になる。 | `runSectionRegen` |
| S6 | 帯の付いた語は、例文・チャンクを**その帯の行からだけ**読む。共有の語の行（`words`）や言語の置き場の例文・チャンクは出さない。行がまだ無ければ空（作りに行く）。 | `getWordExplanation`、iOS `ReaderLanguage.resolve` |
| S7 | 例文・チャンクを作る指示のレベルは、帯の代表の級（現状 = 現状の帯の下の級、目標 = 目標の帯の上の級）。同じ帯の誰が作っても同じ指示になる。 | `bandLevels` |
| S8 | **表示言語が違う人とは何も共有しない**。別の言語の行の学ぶ言語の部分（チャンクの文・量詞など）も出さない（R23 の「学ぶ言語の部分だけ残す」をやめた）。 | iOS `ReaderLanguage.resolve` |

## 移行

1. 先に新しいサーバ関数を配る。表・列がまだ無い間は、全員を `legacy` として今までどおり動く（壊さない）。
2. 次に移行（`20261025120000_level_content.sql`）を当てる。今ある札はすべて `legacy` になり、それ以後に保存した札に帯が付く。
